# 开发历程与踩坑记录

> 本文件承接 README 移出的历史记录：**AI 交互方式**、每轮做了什么、判据抓到过的真 bug 与反向验证。
> README 只保留最近三轮更新与当前状态；要看"为什么这样做"，从这里往回翻。

## 一、AI 交互方式（本项目实际采用的工作流）

1. **每轮一个主题**，一轮内完成"实现 → 判据 → 反向验证 → 文档 → 提交"；
2. **判据只增不减**：新增能力必须配一条**能失败**的断言，且**反向验证**过（故意改坏 ⇒ 必须红）；
3. **一份事实只写一处**：分组规则、图表标题、聚合口径、依赖追踪都收敛到单一来源；
4. **先核实再动手**：清单里的想法先验证是不是真问题（例如"回放时柱状/雷达没跟当期"核实后是白做，遂改为判据）；
5. **产物要可复现**：涉及产物的改动必须"重跑不变"（连跑三次比对哈希）；
6. **上下文与教训落盘**：跨会话的记忆文件记录口径、纪律与踩过的坑（不进仓库）。

## 三、历史记录（按时间倒序，最新在前）

### 这些判据实际抓到过的真 bug（都写进代码注释了）

1. **道格拉斯-普克对闭合环退化**（弦长为 0 ⇒ 所有点被判共线删掉）：78 块地只收下 5 块；
2. **拿全年 GDD 比冬小麦需求** ⇒ 误判"偏热"；实测数据还纠正了我对玉米积温的预期；
3. **跨年数据的"年降水"直接求和**（549 天合计当成一年）；
4. **果园不在作物表 / 牧草被要求"播种"**；
5. **病害传播误用"等级"当源强**（健康地块等级=1 也天天往外传）；
6. **收获月日没按播种年归位**：`'10-13' >= '07-25'` 成立 ⇒ **播种当天就收获**，
   479 块地全都长不到成熟、区域进度峰值只有 0.47（修好后 0.98）；
7. **区域聚合的分子/分母不同源** ⇒ 面板出现"水分保持 127%"；
8. **告警拿促病指数(0~1)去比等级 3** ⇒ 地图永远显示 1 级绿、告警永不触发；
9. **漏了 `leaflet.js` 的 script 标签**（只引了 CSS）⇒ `L is not defined`；
10. 浏览器检查里"只查 canvas 存在"会**假通过**（Leaflet 会吞掉事件处理器里的异常，HTML 写进去了、
    画曲线的代码没跑）⇒ 改成查 `canvas.style.height` 是否被真正设置；
11. **OSM 路网碎片化**：两条路几何相交却不共享节点 ⇒ 直接建图会让 120 块地被判成"不可达"。
    修法是节点吸附合并（15 m 内同一节点），并加了一条"连通分量体检"把这件事**报出来**；
12. **地块时间与栅格口径不一致**（地块用"最近节点"、栅格用"全节点最小"）⇒ 两者对不上，
    而且"最近节点"落在孤立碎片上就会产生假不可达。统一成"全节点取最小"，另把"下道距离"单独记下来当盲区信号；
13. **等时圈层级写死 15/20 分钟** ⇒ 在"全程 ≤13 分钟"的乡镇上永远是 0 段（空图层）。
    改成按本地区 p25/p50/p75/p90 定层级，并加判据"每一层都必须有线段"；
14. **邻接判定用"顶点到顶点"** ⇒ 把真实相邻的地块判成几十米远（T 型接头 + 抽稀），聚合候选对从上千掉到 199；
15. **把"同作物"当经营单元的约束** ⇒ 501 块只合出 351 个单元（随机作物下相邻同作物概率仅 ~1/7）；
16. **CSV 解析没去掉 `\r`** ⇒ 若仓库检出成 CRLF，`synthetic === '1'` 会假失败（已加 `.gitattributes` 统一 LF + 解析去 `\r`）；
17. **首屏背了 2.4 MB 的分区样点**（12000+ 个点）⇒ 改成**按需加载**（打开图层才拉），
    并加判据"加载前图层不存在、打开后要素数正确"；
18. **`--bbox` 的顺序是 `S,W,N,E`**：我按 `W,S,E,N` 拆了一次，于是 bbox 变成"经度当纬度"，
    Overpass 安静地返回 **0 个关系** —— 差点得出"这里没有行政边界"的错结论（真相是"我传错了参数"）。
    同一条路线上还踩到：**主站过载时会返回 HTML 报错**，而"关系 + bbox"这种查询甚至能不报错地返回空；
    所以取数改成 `is_in(点) → 按名字取几何` + **多镜像轮询**，并把诊断计数打出来（几个关系/几段线/几个点）。
19. **Leaflet 1.1.1 的 `resetStyle()` 会把样式复原成"默认蓝"**：因为它把 `options.style` 这个**函数**
    拷进 `layer.options`，`_updateStyle` 读不到 `fillColor`/`color` 就落回默认样式。现象是用户报的
    "表格高亮了很多地块但**取消不掉**"（越点越蓝）。修法：**不复原、按当前变量重算**
    （`restoreStyle` / `clearHighlight` 走 `styleFor(feature)`）；`mouseout` 同一个坑一并修掉；
20. **速度表手抄导致"前后对比"全是假的**：`scenario.mjs` 里我手抄了一份路网速度表（motorway 写成 100，
    实际 80），复算现状与 `access.json` 差了 **2.33 分钟** —— 差值不是"新建带来的改善"而是"两套算法的差"。
    修法不只是改数字，而是把参数抽成 **`tools/road-speeds.mjs` 共享模块**（两份副本必然漂）；
    并保留**自检**：复算现状必须与 `access.json` 差 < 0.05 分钟，否则直接报"对比不可信"；
21. **情景推演的语义错误**：新建后必须取 `min(现状, 到新点)` —— 第一版只算了"到新点的时间"，
    于是远离候选点的地块全被算成"恶化"，平均从 4.6 分钟涨到 19 分钟（**截图一眼看出荒谬**）。
    现在有不变量判据守着："任何候选点都不比现状差"；
22. **把分钟值当下标**：盲区面积 `areas[baseMin[i]]` 取到 undefined ⇒ 面积算出 NaN；
23. **`package.json` 被改成非法 JSON + 文档里引用了不存在的脚本**（我凭空写了个 `build-hist.mjs`）⇒
    新增"工程完整性"判据：JSON 必须可解析、npm 脚本引用的文件必须真实存在；
24. **`out tags geom` 会把成员几何挡掉**：关系查询里写 `out tags geom` 拿不到 member 的 geometry
    （诊断显示"关系 2 / 外环 0"），改成 `out geom` 才拿到（68 段线 / 1558 个点）；
20. **`fact_observation` 少了两个维度**（只有"变量×时间"，没有空间层级）⇒ 加 `spatial_level/spatial_id/variable_code`，
    这才叫三维齐全，也才能把地块级/单元级观测并进同一张长表；
19. **编码列被推断成数字**：`09186` 若按数字写进 Excel，**前导零会被吃掉**（`09186`→`9186`），
    `P-000001` 之类的顺序号同理 ⇒ 编码/标识列一律判为文本，并加判据 + 用 openpyxl 反向验证读回值；
20. **导出与页面的时间粒度不同**（导出逐日、页面 7 天抽样）⇒ 必须写清楚：旬表是真日均，不是抽样插值；
21. **`meta_dataset` 静默写成空表**：`writeCsv` 期望对象而我传了数组，所有单元格为空且不报错
    ⇒ 加"每个元素都有名有值"判据才抓到。

### 透视/查询与纯静态这一轮抓到的真 bug

- **`dim_crop` 的 `ORCHARD` 重复**（手写补行时没注意它已在 `CROPS` 里）⇒ 作物字典 9 行只有 8 个唯一码。
  重复键的后果不是"多一行"，而是**任何连接都会静默放大行数** —— 查询引擎拒绝执行才暴露（导出侧本该先抓住）
  ⇒ 加「维度表主键唯一」判据（8 张维度表逐张查）；
- **`dim_source` 的 `osm` 写了两行**（同一来源，只是说明文字不同）⇒ 合并；同样是被上面那条判据抓出来的；
- **"否则就算谷物"的兜底把果园算成了谷物**：`hierarchy_l1` 原来用三元兜底，`ORCHARD` 悄悄落到 `cereal`
  ⇒ 改成**逐类显式映射**（缺映射就是空值，判据直接报）；
- **筛选里的空值被当成 0**：`Number('') === 0`，于是"没有这一列数据的行"会被算成命中；
  而 SQL 侧 `NULL` 比较是"未知（不命中）"⇒ 两套引擎口径不同。**这个差异是交叉验证抓出来的**，不是判据；
- **python → node 传中文变乱码**：Windows 上 Python 的 stdout 默认 cp936，`print(json.dumps(...))` 把中文按 GBK 编码，
  node 按 UTF-8 解码 ⇒ 只含 ASCII 键的对比全通过、含中文列名的整片不匹配。改成**结果写显式 UTF-8 文件**、stdout 只回 ASCII；
- **判据截断了要检查的文本**：先 `slice(0,140)` 再去测 `/服务器/` —— 关键词在后面，判出假失败 ⇒ 取全文再判、只在打印时截断；
- **"单产不许跨口径平均"的判据前提写错了**：原本指望"数据里恰好混了口径"，但 q1 按作物分行 ⇒ 结构上不可能混
  ⇒ 改成用**粗维度**（年 × 季序）反向验证"机制真的会拦"，否则这条判据只是在撞运气；
- **运距告警阈值定在数据之外**：`dim_variable` 里 `T_MIN_STORE` 的告警是 "> 12 min"，而本演示区运距**最大只有 11.8 分**
  ⇒ 这条告警永远不会触发（"看着有、其实没有"的能力最容易被误认）⇒ 阈值如实标注，q5 改用实测分位数（p90 / p50）。

### 本轮（导览页滚动）抓到的真 bug / 教训

- **共用 `style.css` 就要接手它的"整屏不滚"**：`style.css` 给模拟页写了 `body { overflow: hidden }`
  （grid 整屏布局），导览页是长文档 ⇒ 必须显式覆盖成 `overflow-y: auto`，否则只能看第一屏。
- **判据要断言根因，不能只看现象**：第一版判据只查"能不能滚到底"，而 `height:auto` 恰好也能滚
  ⇒ 把修复回滚后判据**照样绿**（假通过）。改成断言 `getComputedStyle(body).overflowY !== 'hidden'`，
  回滚时立刻红（`body.overflow-y = hidden`）。
- **`.step b { display:block }` 会命中正文里的内联 `<b>`**：结果"季度刻度"被顶成单独一行
  ⇒ 标题规则要收窄成 `.step > b`。

### 本轮（产物稳定性）抓到的真 bug / 教训

- **`csv.writer` 默认行尾是 `\r\n`**：`duck-run.py` 用 `open(..., newline='')` 打开再交给 `csv.writer`，
  于是产出的 CSV 是 CRLF，而 git 索引存 LF ⇒ **每次重跑都在提交里塞进"整文件改动"**（纯换行差异，
  把真改动淹掉）。改成 `lineterminator='\n'`，并加判据扫 `tables/**/*.csv` 前 64 KB 不许有 `\r`。
- **SQL 没有 `ORDER BY` 就没有行序保证**：同一条"小麦/籽粒/2025"在两次运行间换了行号 ⇒ 产物 diff 抖动。
  写出的 CSV 按行内容排序（只影响**给人看的产物**，用于逐格比对的 `rows` 保持原样）。
  验证办法不是"看一眼"：**连跑三次、对产物算 md5，三次一致**才算根治。
- **"整文件 diff"先别当成内容变化**：本次 16 个文件全是行尾/行序，`--ignore-cr-at-eol` 之后仍显示
  改动，才顺着查到"行序"这一层 —— 只看 `git diff --stat` 会误判成"数值变了"。

### 上一轮（交付包）抓到的真 bug / 教训

- **静态核对 ≠ 交付物能起来**：包里 5 条判据（表数/字节数/按需/引用/缓存）都是**静态**的，
  页面真跑起来才说明"这份交付物打开是好的" ⇒ 加了 `pack --smoke`：给 browser-check 加 `--root`，
  对着**包目录**跑同一个冒烟。反向验证：删掉包里的 `data/weather_daily.json` ⇒ 退出码 1，且直接说
  `data/weather_daily.json → HTTP 404`；放回去 ⇒ 5/0。
- **标签必须随模式变**：`--with-daily` 时按需表本来就该在包里，判据标签却还写着"包里没有 gitignore
  忽略的东西" ⇒ **自相矛盾**（同一条输出里先说"没有"再说"已带"）。标签要么跟着模式走，要么别写死。
- **规则只写一处**：`deliver`（写清单）与 `pack`（打交付包）必须用同一套分组，否则"清单说必带、
  包里却没有"。已抽成 `tools/lib/deliver-groups.mjs`，两边 import 同一份。

### 本轮（交付清单）抓到的真 bug / 教训

- **"四舍五入成 0"会把小表误判成空文件**：交付清单判据原本用 `(size/1024).toFixed(0) > 0`，
  而 `dim_admin` 只有 2 行（**<1 KB**）⇒ 显示 `0 KB`、判据红。改成用**字节**判断存在性/非空，
  显示时才换单位（`<1 KB`）。同理：`14048 KB` 也不该再拼一次 ` KB`（模板里出现了 `2 KB KB`）。
- **"未被查询读" ≠ "可以删"**：交付清单里必须写这句 —— 它可能仍被 Excel 导出、数据元字典、
  离线校验用到；把"查询不读"当成"可以删"是最容易犯的越界。
- **审计命令不该顺手写产物**：`--deps` 一开始沿用了 `--web`，每次审计都把 `data/pivot.json`
  重写一遍（只差时间戳）⇒ 已让 `--deps` 跳过网页产物。

### 本轮（列级依赖）抓到的真 bug / 教训

- **静态扫描 vs 真实访问**：上一版 `cols` 用「词边界匹配」判断列有没有被用到，`name`/`level`/`crs`
  撞上注释与文案就算「用过」⇒ 206 列全绿，**等于什么都没查**。改成 Proxy 记录真实属性访问，
  结论才立得住（核心表 34/34、15/15、26/26 全被读到；`fact_parcel_daily` 一条都不读）。
- **⚠️ 别用「切片 + 拼接」改文件**：本轮写补丁脚本时用 `s = s[:i] + NEW`，**把文件后半段整段丢了**
  （判据从 22 条掉到 19 条）。当场被 `git diff --stat` 拦下，`git checkout` 恢复后
  **改用逐处精确替换**重做。教训：改文件只用「精确替换」；需要截断时先备份并**断言长度**。
- **「未读」不等于「可删」**：审计输出必须自带这句 caveat —— 这些表仍可能被 Excel 导出、数据元字典、
  离线校验用到；把「查询不读」当成「可以删」是最容易犯的越界。

### 上一轮（依赖追踪 / --only）抓到的真 bug / 教训

- **追踪代码要先把状态初始化好**：给 `TableStore.get` 加追踪时忘了在构造器里建 `this.reads`，
  第一条查询构建就 `TypeError` —— 这类"新增状态忘初始化"只有**跑一次**才发现（`node --check` 看不见）；
- **声明会漂，追踪不会**：本想"让每个查询声明依赖的表"，但人工声明只是又一份需要维护的文档；
  改成运行时追踪后，依赖是**副产品**，还能顺手做成"0 依赖 = 表名写错"的判据；
- **同一件事反复测得不一样，就要承认没定位**：`--xlsx` 增量从 2.6s 到 1.5s 之间波动，而内部只有 100ms。
  如实写"未定位"，比编一个"可能是 GC"的解释更有用。

### 上一轮（--xlsx 调查）抓到的真 bug / 教训

- **优化前先量"要优化的那个东西"**：整个第 2 项（共享字符串表）建立在"文件大、字符串重复多"的假设上，
  一量就垮 —— 产物 98 KB、`writeXlsx` 只要 ~100 ms、而且 **deflate 早就开着**。**假设没验证就动手，等于白改**；
- **注释与代码不一致会误导后来人**：writer 头注释写着"STORE 不压缩"，代码里 `useDeflate` 明明在 deflate；
  这种"文档说 A、代码做 B"比没有注释更糟（它让人以为性能问题出在压缩上）；
- **测不出来的东西要如实说**：`--xlsx` 整轮慢 1.8–2.6 s 但内部分段只有 100 ms，原因没定位
  （怀疑本机 I/O/杀软），**不编解释、不据此改代码**。

### 上一轮（-v / 列扫描收紧）抓到的真 bug / 教训

- **`-v` 一上线就抓到一条假失败判据**：模型冒烟里"单次 < 5 s"的墙钟阈值，在机器有其他进程烧核时
  （实测 6659 ms）**直接判红** —— 而我前一轮刚在 `query` 那边写过"墙钟随机器变、不设阈值"。
  **同一条原则要贯穿全仓**：改成软提示（5 s 参考线）+ 硬顶 30 s（只防数量级回归）；
- **"全都有引用"这种结论要看匹配规则**：上一版按"词边界任意出现"扫，`name`/`level`/`crs` 撞上注释就"算用过"；
  收紧到代码上下文（`r.<col>` / `x['<col>']` / `<col>:`）之后结论**没变**，这才说明它真是"没有孤立列"；
- 顺便确认：环境被 IDE hook 拦过一次，编辑**执行前**就被拒绝 ⇒ 仓库没有半成品状态（这也是"改动要么全落、要么全不落"的好处）。

### 上一轮（ready 汇总 / 列扫描 / 分支补齐）抓到的真 bug / 教训

- **判据抓到了我改 `ready` 时的漏项**：`ready` 换成 runner 后，`package.json` 里不再有 `smoke:browser` 字样
  ⇒ 那条"`ready` 必须含页面冒烟"的判据立刻红 ✔。修法不是放宽它，而是让它**去 runner 的步骤表里查**

  ⇒ 改成按**图表声明本身**核算，并另加"范围正好覆盖数据行、不含合计行"的断言；
- **"人工核过"不是判据**：原来 Excel 那条只查了 ZIP 头和体积，说明里写"另用 openpyxl 人工核过可打开" ——
  现在改成真读回来核对图表（类型/标题/引用/缓存点数）。

### 上一轮（排产看板前置：修掉伪峰 + q14）抓到的真 bug

- **窗口边缘伪峰**（这条是靠"页面说 2024-07-01 最忙、季表那天一张季都没有"对出来的）：

  ⇒ 必须按**作物的收割期**判（`c.harvestMD <= startMD` 则整年不记）；
- **q14 的运力占用结论**（不是 bug，但值得记）：最堵的一天 **2024-09-20**（104 块 / 248.8 ha / 9117 t，

### 上一轮（四张图 / 两张表进页面）抓到的真 bug

- **时间维没按时间排**（这条是**看截图**才发现的，像素判据证不了）：农事日历的月份是"首次出现顺序"，

- **排序位置错了**：第一版把排序放在"算完 matrix 之后"，键换了位置、值没跟着换
  ⇒ 判据当场报"2024-04 行合计 227 ≠ 57"（矩阵与键必须**同一处**排好）；

- **我自己在注释里写了没量过的数**："地图区 730px" —— 实测 1440×900 是 **794px**、1024×640 是 378px。
  这类"看起来像实测的估计值"最容易被当真（这个项目的规矩是数字必须可追），
  于是把结论做成判据（量两个尺寸、报劈半后的宽度），注释里的数换成量出来的。

### 上一轮（口径上页面 / 网格表 / 农事日历）抓到的真 bug

- **"无数据"与"0"被混成一个数**：某网格全是牧草/果园（不播种）时，进度**没有意义**，
  表格却显示 `0.0%`（读成"一点没长"），而地图给的是"无数据灰" ⇒ **同一个格子两个说法**。
  现在聚合成 `null`、表格渲染 `—`；坑在渲染处 —— **不能先乘 100 再判空**（`null * 100 === 0`，又变回 0.0%）；
- **判据容差要按显示精度定**：表里是"1 位小数的百分比"，我却拿 `1e-6` 去比 ⇒ 假失败（改成 0.1%）；
- **`null` 不该送进色带**：判据复算得到 `null`（该网格没有可聚合地块）时，`colorOf(null)` 返回色带最低档的深色，
  而页面画的是"无数据灰" ⇒ 假失败。判据必须和页面用**同一条空值规则**；
- **模板字符串会把 `\s`、`\n` 吃掉**（与"注释里不能写反引号"是同一个坑的两个兄弟）：
  判据里写 `replace(/\s+/g,' ')` 实际发到浏览器的是 `/s+/`（替换字母 s），换行原样留着 ⇒ 带 `$` 的断言假失败；
  `split('\n')` 会变成**真换行**把浏览器里的字符串写断（报"Invalid or unexpected token"）⇒ 用 `String.fromCharCode(10)`；
- **懒加载的数据要等它落回来**：`ensurePivot()` 只把请求发出去、**自己返回 `undefined`**，
  `await ensurePivot()` 什么也没等到（读到 0 个视图）⇒ 轮询 `ui.pivotData` 出现为止；
  同轮还有一条同类的：**表格是按"当前页签"渲染的**，停在别的页签上读到的就是别的表 ⇒ 先切页签再读；
- **仓库卫生判据当场抓到我漏删的临时脚本**（`tools/_calendar.py`）—— 这条判据的存在价值就是"防我自己"。
