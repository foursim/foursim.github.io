# 农业监测 · GIS 可视化

一个**乡镇尺度**的农业监测看板：**地块、路网、设施是真的**（OpenStreetMap），
**监测值（气温/湿度/土壤水分/生长进度/病害扩散/水肥保持/耕作·休耕·收获·产量）由本项目模型生成**，
真实气象（NASA POWER）只当**校准锚点与验收基准**。纯静态、无构建、无后端、运行时零外部请求 ——
丢到 GitHub Pages 上就能跑。

演示区：**Hallertau · Wolnzach（德国巴伐利亚，世界最大啤酒花产区）**，15 km² 内的
**501 块地 / 990 ha**，549 天（2024-07-01 ~ 2025-12-31，含冬作物完整跨年生育期）。

> 前身是一个六边格贸易游戏。经济循环、商队、任务列表、道路铺设那一套**已全部作废**
> （它当初只是为了验证"道路与地点数据展示"），只保留了"路网 + 地点"作为监测数据的空间载体。

## 快速开始

```bash
npm run data:all        # 取数 + 分层 + 分区 + 合理性校验 + 导出表格（一条命令跑完）
                        #   = parcels → roads → poi → weather → access → units → zones → check → export:tables
npm test                # 模型判据 38 条
npm run test:browser    # 真浏览器验收 43 条（Chrome/Edge，找不到浏览器时自动跳过）
npm run export:tables   # 单独重跑表格导出（含 15 条导出判据，失败即非 0 退出）

npm run serve           # 启动静态服务器 → 打开 http://localhost:8080/
npm run serve:sub       # 同上，但挂在子路径下 → http://localhost:8080/webtrade/
npm run serve:lan       # 再打印局域网地址，手机同网段可直接打开（测窄屏）
```

⚠️ **必须走 http 服务**：`file://` 直接双击 `index.html` 会被浏览器的 ES 模块与 CORS 规则拦住
（模块脚本、`fetch('data/*.json')` 都不允许），页面会停在"页面初始化失败"。

`tools/serve.mjs` 是零依赖的 node 静态服务器（不用 python、不用 `npx serve`）：
`.geojson` 会给对 `application/json`、响应带 `no-store`（改完刷新即生效）、
并且支持 `--prefix` —— **子路径模式才是 GitHub Pages 项目站的真实形态**（`user.github.io/<repo>/`），
相对路径写错只有这样才能发现。

> Git Bash 用户在命令行直接传 `/webtrade` 会被 MSYS 改写成 `C:/Program Files/Git/webtrade`
> （Windows 路径转换）—— 所以 `serve:sub` 里写的是**不带前导斜杠**的 `--prefix webtrade`，
> 服务端两种写法都接受。手动跑就写 `--prefix webtrade`。

## 什么数据是真的，什么是模型生成的

| 层 | 来源 | 说明 |
|---|---|---|
| 地块几何 | **真实** | OSM `landuse=farmland/meadow/orchard/vineyard`，ODbL（署名即可商用） |
| 路网 | **真实** | OSM `highway=*`（含 `track` 田间道 —— 农机进出靠它） |
| 农业设施 | **真实** | OSM 的筒仓/谷仓/农机库/农资店。**OSM 是自愿标注，乡村覆盖不全，数量少是真实情况** |
| 气象 | **程序生成 + 实测校准** | 生成器只吃该站三个实测统计量（年均温、年振幅、雨日频率），季节相位/天气过程/日较差/辐射/湿度结构都得自己长出来；验收时与同期 NASA POWER 对比 |
| 作物 / 农事 / 产量 / 病害 / 水肥 | **模型生成** | 不是观测数据，不能当农情依据 |

`data/parcels.geojson` 里每块地都带 `crop_source: "simulated"`，界面的"说明"弹窗也如实写着这件事 ——
**不要把模拟值当观测值**是这类看板的第一条纪律。

## 模型口径（每条都能被数据打回）

1. **适种性由积温决定**。本区实测（NASA POWER，按各自生育期窗口算）：
   冬小麦 2615、冬油菜 1674、**青贮玉米 986**、啤酒花 1750 ℃·d；
   **粒用玉米需要 1400+ ⇒ 不适宜**，所以作物结构里根本没有它 ——
   与德国真实作物结构一致（青贮玉米 206 万 ha vs 粒用 42.9 万 ha）。
2. **积温按生育期窗口算**：冬小麦是"上年 10 月播 → 次年 7 月收"，拿全年 GDD 去比作物需求是量纲错误。
3. **收成/农事按季推进**：每季有自己的 `{播种日, 收获截止日}`；收获要么积温达标，要么到农事日历的硬日子
   （晚播青贮玉米不会等到霜前）；休耕地块没有播种与产量。
4. **病害是时空过程**：先按温湿算促病指数（**RH 低于阈值直接归零**），再按风向在邻域传播
   （用促病指数当源强，不是用等级 —— 等级从 1 起，用等级当源强会让健康地块天天"传染"）；
   约 55% 的地块有药剂防治，病情被封在 3 级以下。
5. **生长进度** = 积温累积 / 该作物需求；**水肥保持** = 根区湿度 × 地块土壤质量，与"基肥 − 吸收 − 淋失"。
6. **告警阈值按本地区分位数定**（水分 p15/p85、生长期气温 p2/p98、日降水 p97、病害 ≥3 级）。
   绝对阈值换个地区立刻失效：本区根区湿度只有 0.61~0.80、生长期日均温最高 25.7 ℃。

## 三层空间单元（P1 自然田块 / P2 经营单元 / P4 统计网格）

参照欧盟 **LPIS** 把"稳定身份"与"逐年属性"分开的做法（`agricultural parcel` = 单一作物+单一农户的连续地块，
见 [FIG 2007](https://www.fig.net/pub/fig2007/papers/ts_1g/ts01g_03_inan_cete_1404.pdf)；LPIS 对外发布还有**匿名化**版本）：

| 层 | 是什么 | 本区结果 | 用途 |
|---|---|---|---|
| **P1 自然田块** | OSM 真实可见田块边界（`data/parcels.geojson`） | **501 块** / 990 ha / 中位 1.12 ha | 逐块作业与监测 |
| **P2 经营单元** | **空间连片的作业片区**（地块间距 ≤30 m、面积上限 30 ha，贪心合并） | **62 个** / 面积中位 19.7 ha / 最大 30 ha | 轮作计划、作业编组、管理口径 |
| **P4 统计网格** | 250 m 规则网格（按经纬度取整编码，可复现；思路同 OGC API – DGGS） | **217 格** | 汇总上报 |
| P3 管理分区（**演示**） | 25 m 网格采样 + 一维 k-means 分 2~3 区（方法同精准农业的 management zone）；`data/zones.geojson` 2.4 MB ⇒ **按需加载**（打开图层才拉） | 363 块地 / **12833 样点** / 744 区 | 变量施肥/灌溉的处方图雏形 |

两条被数据打回来的设计决定（都写进注释了）：

1. **"经营单元"不能要求同作物**。本区地块确实是连片马赛克（456/501 的最近邻 ≤5 m、中位距离 0 m），
   但**同作物相邻极少** —— 作物是逐地块抽的，任意相邻对同作物的概率只有 ~1/7；
   拿它当约束，501 块只能合出 351 个单元（等于没聚合）。语义上也该如此：**单元是空间单元，作物是属性**。
2. **邻接必须按"点到线段"算**。第一版用"顶点到顶点"，把真实相邻判成几十米远（T 型接头 + 抽稀后顶点稀疏），
   相邻候选对从上千对掉到 199 对。

## 可达性分析（算出来的，不是摆上去的）

路网早就有（1576 条路段，含田间道），但之前只是**背景画线**。`tools/build-access.mjs` 让它回答农业物流里
最实际的问题：**这块地到最近的收储点要走多久、谁的田头够不着？**

- 图：OSM 路段折点做节点、haversine 边长、按 `highway` 等级给速度（motorway 80 → track 12 km/h）；
- 源：OSM 的 `silo / barn / agrarian / marketplace` 共 **15 个**；
- **多源 Dijkstra** 一次算出"到任意收储点"的最短时间；再按 10 km/h 补一段"地块质心 → 路网"的接驳；
- 等时圈：规则网格上的时间场 + marching squares 抽等值线。

本区结果：**中位 4.4 分钟、p90 7.7 分钟、最远 11.8 分钟，0 块不可达**；
"下道距离" p90 = **433 m**（这才是真正的盲区信号：离路网越远，农机下道成本越高）；
等时圈层级 **3 / 4.5 / 6 / 7.5 分钟**（按 p25/p50/p75/p90 定 —— 写死 15/20 分钟在"全程 ≤13 分钟"的乡镇上
会是空图层）。

⚠️ 三个如实声明的局限：接驳段是直线（不是田间实际路径）、速度是等级经验值（不是限速）、
栅格分辨率 56×56。所以**只看相对格局，不要当成精确行程时间**。

## 界面

- **顶栏**：时间轴（549 天，可拖可播，1×/4×/12×，空格播放）；
- **左栏**：指标切换（作物/生长进度/病害等级/水分/养分/耕作状态/**到收储点**/单产）、色带图例、图层开关
  （地块着色·边界·路网·设施·区域气温·**等时圈**）；
- **地图**：地块着色 + 路网 + 设施点 + 区域气温圈；点地块出详情；**不画底图**（见下）；
- **右栏**：区域概览（气温/湿度/降水/进度/水肥/病级/累计收获/**到收储点中位与最远/下道距离 p90**）、作物结构条形、

底图只会抢注意力。图层结构已经预留，将来要加一层 `L.tileLayer` 即可。

## 判据（模型 38 + 真浏览器 43 + 数据 25 + 导出 15 = **121 条**）

模型判据里刻意放了**能失败**的断言，例如：
- 把湿度压掉 40 个百分点 ⇒ 病害必须**完全不出现**（钉住"病害由温湿驱动"）；
- 每块地的作物必须满足"实测积温 ≥ 该作物需求"（钉住适种性，粒用玉米因此长不出来）；
- **没有粒用玉米**、青贮玉米需求 ≤ 实测 986 ℃·d；
- 生成气象 vs 实测：月均温相关 r > 0.85、年均温偏差 < 2 ℃、年降水与 RH 水平可比；
- 区域聚合指数恒在 [0,1]（分子分母必须统计同一批地块）；
- 同种子逐位可复现。

数据侧（`npm run data:check`）另有可达性判据：每块地都有可达时间、量纲合理（0~120 分钟）、
中位落在乡镇尺度、"下道距离" p90 < 1 km、**没有被判成"不可达"的地块**（假不可达说明路网碎片没处理干净）、
等时圈层级严格递增且**每一层都真的画出了线**。

浏览器判据用**真实鼠标事件**在**子路径部署**（等价 `user.github.io/<repo>/`）下验收：指标切换真的改到
地图、时间轴/播放真的推进、图层开关真的增删、点地块真的出曲线、点告警真的定位，
外加三个尺寸的可达性审计（尺寸为 0 / 被遮挡 / 滚不出来）。

### 这些判据实际抓到过的真 bug（都写进代码注释了）

1. **道格拉斯-普克对闭合环退化**（弦长为 0 ⇒ 所有点被判共线删掉）：78 块地只收下 5 块；
2. **拿全年 GDD 比冬小麦需求** ⇒ 误判"偏热"；实测数据还纠正了我对玉米积温的预期；
3. **跨年数据的"年降水"直接求和**（549 天合计当成一年）；
4. **果园不在作物表 / 牧草被要求"播种"**；
5. **病害传播误用"等级"当源强**（健康地块等级=1 也天天往外传）；
6. **收获月日没按播种年归位**：`'10-13' >= '07-25'` 成立 ⇒ **播种当天就收获**，
   479 块地全都长不到成熟、区域进度峰值只有 0.47（修好后 0.98）；
7. **区域聚合的分子/分母不同源** ⇒ 面板出现"水分保持 127%"；
8. **告警拿促病指数(0~1)去比等级 3** ⇒ 地图永远显示 1 级绿、告警永不触发；
9. **漏了 `leaflet.js` 的 script 标签**（只引了 CSS）⇒ `L is not defined`；
10. 浏览器检查里"只查 canvas 存在"会**假通过**（Leaflet 会吞掉事件处理器里的异常，HTML 写进去了、
    画曲线的代码没跑）⇒ 改成查 `canvas.style.height` 是否被真正设置；
11. **OSM 路网碎片化**：两条路几何相交却不共享节点 ⇒ 直接建图会让 120 块地被判成"不可达"。
    修法是节点吸附合并（15 m 内同一节点），并加了一条"连通分量体检"把这件事**报出来**；
12. **地块时间与栅格口径不一致**（地块用"最近节点"、栅格用"全节点最小"）⇒ 两者对不上，
    而且"最近节点"落在孤立碎片上就会产生假不可达。统一成"全节点取最小"，另把"下道距离"单独记下来当盲区信号；
13. **等时圈层级写死 15/20 分钟** ⇒ 在"全程 ≤13 分钟"的乡镇上永远是 0 段（空图层）。
    改成按本地区 p25/p50/p75/p90 定层级，并加判据"每一层都必须有线段"；
14. **邻接判定用"顶点到顶点"** ⇒ 把真实相邻的地块判成几十米远（T 型接头 + 抽稀），聚合候选对从上千掉到 199；
15. **把"同作物"当经营单元的约束** ⇒ 501 块只合出 351 个单元（随机作物下相邻同作物概率仅 ~1/7）；
16. **CSV 解析没去掉 `\r`** ⇒ 若仓库检出成 CRLF，`synthetic === '1'` 会假失败（已加 `.gitattributes` 统一 LF + 解析去 `\r`）；
17. **首屏背了 2.4 MB 的分区样点**（12000+ 个点）⇒ 改成**按需加载**（打开图层才拉），
    并加判据"加载前图层不存在、打开后要素数正确"；

    ⇒ 加"每个元素都有名有值"判据才抓到。

## 部署（GitHub Pages 项目站）

把目录内容推到仓库，Settings → Pages → Deploy from a branch 即可。没有构建产物、没有绝对路径、
没有 `.js/.css/.json/.geojson` 之外的可执行资源、**运行时零外部请求**（Leaflet 已本地内置）。
数据总量约 0.8 MB（其中路网 470 KB），加 Leaflet 约 1 MB。

## 已知限制 / 下一步

- **气温是区域量**，不做地块级着色：OSM 不提供每块地的高程，硬编一个地块级温度场就是造假。
  将来接入 DEM（如 Copernicus GLO-30）后可以按高程递减率做出真实的空间差异。
- **产量/病害没有实测对照**：目前只能用公开统计（单产区间）与农学阈值（温湿—促病）做间接校验。
  要更进一步，需要接入真实产量统计（USDA NASS / Eurostat / 县级统计年鉴）或遥感（Sentinel-2 NDVI）。
- 可达性用的是**等级经验速度 + 直线接驳**；要更准需要真实限速/路面数据，或上 Valhalla/OSRM
  （本乡镇规模自建 Dijkstra 已经够，不必引外部服务）。
- 等时圈目前是**等值线**（不是填充面片）；要填充需要把 marching squares 的输出接成多边形。
- 演示区可换：改 `tools/fetch-data.mjs` 的 `--bbox` 与 `--lat/--lon` 即可（任何 OSM 覆盖良好的乡镇）。
- 仓库**还没有 git**（`git init` 之后建议把 `data/` 与 `vendor/` 一起提交，它们是可复现的取数产物）。
